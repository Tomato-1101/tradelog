# ペーパートレード イベント契約（panel → web）

発注小窓（`apps/panel`）が追記し、web（`apps/web`）が取り込む。**追記専用**。既存行を書き換えない・消さない。

- 置き場所: `data/paper/events.jsonl`（1 行 1 イベントの JSON、UTF-8、改行 `\n`）。スクショは `data/paper/shots/YYYY-MM-DD/<event id>.png`。
- `data/paper/` は git 管理外（リポジトリは PUBLIC）。
- 取り込みは冪等: `id` が既に取り込み済みなら無視する。
- 時刻 `ts` はミリ秒付き ISO8601、JST オフセット付き（例 `2026-10-05T09:01:23.456+09:00`）。DB には UTC で保存する。
- 価格・数量は **文字列の10進数**（浮動小数を経由させない）。数量は株数。
- 本物の発注は存在しない。panel は外部に一切送信しない（このファイルへの追記だけ）。

## 共通フィールド
| key | 型 | 説明 |
|---|---|---|
| `v` | 1 | 契約バージョン |
| `id` | string(UUID) | イベント ID（一意） |
| `type` | `order` / `fill_mark` / `cancel` / `memo` | |
| `ts` | string | 押した瞬間の時刻 |

## `order`
| key | 型 | 説明 |
|---|---|---|
| `position_id` | UUID | 建玉 ID。新規建てで panel が発行、決済・買い増しは既存の ID |
| `intent` | `open` / `add` / `close` | |
| `symbol` | string | 東証コード（例 `7203`, `285A`） |
| `side` | `buy` / `sell` | open+sell = 空売り |
| `qty` | string | 株数 |
| `order_type` | `market` / `limit` | |
| `limit_price` | string \| null | 指値のみ |
| `shot` | object \| null | 発注時の HYPER SBI 2 画面（撮れなかったら null） |

`shot`:
| key | 型 | 説明 |
|---|---|---|
| `path` | string | `data/paper/` からの相対パス |
| `price_text` | string \| null | 現在値領域の読み取り生文字列 |
| `price` | string \| null | 数値として解釈できた現在値（カンマ除去済み）。不確かなら null |
| `symbol_text` | string \| null | 銘柄コード領域の読み取り生文字列 |
| `confidence` | number \| null | 読み取り信頼度 0〜1 |
| `captured_at` | string（任意） | 撮影できた時刻（`ts` と同じ形式）。`ts`（押した瞬間）との差が撮影の遅れ |
| `window_title` | string（任意） | 撮ったウィンドウのタイトル（例 `全板　フジクラ(5803)`。全角スペース区切り） |
| `ocr_path` | string（任意） | 全画面 OCR のサイドカー（`data/paper/` からの相対パス）。order を書いた後に裏で書くので、まだ無いことがある |

`price_text` / `price` / `symbol_text` / `confidence` は「読み取り領域」を設定した時の読み取りだけ（未設定なら null）。
自動読み取り（下記）の結果はサイドカーの `auto` に書く。`captured_at` 等の 3 キーは 2026-10-05 以降の行にだけあり、無い行もある（`v` は 1 のまま）。

## `fill_mark`（指値が約定したと本人が判断して押した）
`order_id`（対象の order の id）。web 側で以降の 1 分足と照合して確定/要確認にする。

## `cancel`（指値の取消）
`order_id`。当日中に `fill_mark` も `cancel` も無い指値は、引け後に失効扱い。

## `memo`
`position_id`（必須）, `order_id`（任意）, `text`（音声入力の文字列そのまま）。建玉中・決済後いつでも追記できる。

## 約定価格の確定規則（web 側）
1. 板寄せの時間帯の成行 → その板寄せの価格・時刻で約定。足が無ければ「未確定」。
   - 寄り前（〜08:59:59）→ 日足始値・09:00。昼休み（11:30〜12:29）→ 12:30 の分足始値・12:30。
   - 引けの板寄せ（15:25〜15:29）→ 日足終値・15:30。大引け後（15:30〜）→「未確定」。
2. 連続売買中の成行 → `shot.price`。その分の 1 分足があれば [low, high] 内か照合、無ければ日足 [low, high] で照合。
   読めない・範囲外 → その分の足の close を仮置きして「要確認」。足も無ければ「未確定」。
3. 指値:
   - 板寄せの時間帯に出した指値は、板寄せの価格が指値以内（買い: ≤ / 売り: ≥）ならその価格で約定。
   - 連続売買中は、規則 2 で確定に使う「検証済みの現在値」（`shot.price` がその分の 1 分足内 → それ、だめなら
     `auto.price` が 1 分足内 → それ、1 分足が無ければ `shot.price` を日足で照合）が指値以内（買い: 指値 ≥ 現在値 /
     売り: 指値 ≤ 現在値）なら、発注時刻・その現在値で即約定。実際の約定は現在値付近のため。
     判定と価格に同じ値を使う（足の外の誤読で即約定と判定しない）。検証済みの現在値が無ければ下の通常の判定。
   - 注文の状態は時刻だけで決める（大引けを過ぎて `fill_mark` も `cancel` も無ければ失効）。`fill_mark` 無しで約定した指値
     （即約定・板寄せ）は確定時に「成行と同じ扱い（MARKET）」に直し、失効に数えない。足がまだ無く現在値を検証できない間は
     即約定にしない（大引け後なら失効のまま）。後から足が取れて検証できれば、次の daily で即約定に上がる。
   - それ以外は `fill_mark` の時刻・指値で約定とし、発注〜fill_mark の 1 分足が指値を**越えて**いれば確定（同値は越えていない扱い）、
     越えていなければ「要確認」、足が欠けて判定できなければ「未確定」。
4. 「要確認」「未確定」は web から手入力で確定（`priceBasis = manual`）。

## 両建て禁止とドテン（2026-10-05〜）
panel は 1 銘柄に建玉を 1 つしか持たない（ネッティング）。大きな「買い」「売り」だけで次のどれかを書く。
- 保有なし → `open`。保有と同じ向き → `add`。保有と反対向きで保有数以下 → `close`（一部決済・全決済）。
- 保有数を超える反対売買 = **ドテン**: 同じ `ts` で order を 2 行書く。1 行目 `intent=close`・`qty`=保有数・既存の `position_id`、
  2 行目 `intent=open`・`qty`=超過分・新しい `position_id`。`side`・`order_type`・`limit_price` は 2 行とも同じ、`id` は別。
  `shot` は 2 行で同じもの（画像・サイドカーのファイル名は 1 行目の id）。
  例: 買い 200 保有中に「売り 300」→ close 200 + open(sell) 100。
- 指値のドテン（2 行とも待機中）は、`fill_mark` / `cancel` も 2 行そろって同じ `ts` で書く（片方だけ約定・取消にしない）。
- 待機中の指値との関係（どの順で約定しても両建てにならないように）:
  - 保有なしで同じ向きの新規指値が待機中 → その建玉への `add`。反対向きの新規・買い増し指値が待機中 → 先に `cancel` を書いてから発注。
  - 決済で、決済可能数（保有 − 待機中の決済指値）を超える → その建玉の待機中の決済指値を `cancel` してから、保有全数で判断する。
  - 全決済・ドテンで建玉が終わる → その建玉の買い増し指値も `cancel`。一部決済なら残す。
  - `cancel` は order より前の行に、同じ `ts` で書く。
  - 決済指値の「約定した」で建玉が 0 になる → その建玉に残る新規・買い増し指値を、`fill_mark` の後の行に同じ `ts` で `cancel` する。
- 1 回の操作で書く行（先に書く `cancel`・ドテンの 2 行・相方の `fill_mark` / `cancel`）は 1 回の追記でまとめて書く。
  それでも片方だけ残った行（書きかけ）を読み込んだ場合、panel は補完せず警告だけ出す（ドテンの close 行だけなら全決済と同じ）。
- 旧ルールで書かれた両建ての行（同じ銘柄に買いと売りの建玉）もそのまま有効。web は `position_id` ごとに扱えばよい。

## 全画面 OCR のサイドカー（`shot.ocr_path`）
`data/paper/shots/YYYY-MM-DD/<order id>.ocr.json`。order を書いた後に panel が裏で全画面を OCR して書く（数秒以内。一時ファイルから置き換えるので書きかけは見えない）。
読みにいって無ければ「まだ無い／書けなかった」として扱う。キーは常にすべて書く（値が無ければ null）。
```json
{"v":1,"width":3074,"height":2714,"captured_at":"2026-10-05T15:30:01.234+09:00","window_title":"全板　フジクラ(5803)",
 "auto":{"price":"5566","price_text":"5,566","price_time":"15:30","symbol":"5803","source":"label"},
 "items":[{"text":"現在値","conf":0.3,"x":0.2733,"y":0.0592,"w":0.0189,"h":0.0082}]}
```
- `width` / `height`: 画像のピクセル数（縮小しない実ピクセル）。
- `auto.price`: 現在値（カンマ除去済みの文字列）。`price_text` は読み取った生文字列、`price_time` は現在値の横の時刻 `HH:MM`。
- `auto.source`: `"region"`（読み取り領域で読めた値）/ `"label"`（「現在値」ラベルの右から読めた値）/ null（読めず）。
- `auto.symbol`: ウィンドウタイトルの `(5803)` から。無ければ銘柄コード領域の読み取り。どちらも無ければ null。
  web は `auto.symbol` が読めていて発注銘柄と違えば、別の銘柄の画面とみなして `auto.price` も同じ画面の `shot.price` も約定価格の候補にしない（ラウンドに警告を残す）。`auto.symbol` が null なら従来どおり。
- web はサイドカーが無い・書きかけ・読めない（権限など）ときも daily を止めず、前回読めた値を残して次回読み直す（読めなかった件数は daily の状態に出る）。
- `items`: 画面全体の OCR 結果。座標は画像に対する 0〜1、左上原点。`conf` は 0〜1。Vision が「値」を「值」と返すのは「値」に直してある。

## 自動読み取りの優先順位
- 銘柄コード（小窓の自動入力・`auto.symbol`）: ウィンドウタイトルの括弧内の 4 桁コード（`[(（]([0-9][0-9A-Z][0-9][0-9A-Z])[)）]`。例 `(5803)` `(285A)`）→ 銘柄コード領域の OCR。
- 現在値: 読み取り領域が設定済みで読めた値（`shot.price`）→ 画面全体の OCR で「現在値」ラベルと同じ行の右（次のラベル「高値」の手前まで）を
  切り出して読み直した値。**ラベルが見つからなければ null**（画面のどこかの数字は拾わない）。全画面 OCR の読みと読み直しが食い違えば null。
- 約定価格の規則 2・3 で使う現在値は `shot.price`、それが読めない・その分の 1 分足の外ならサイドカーの `auto.price`（1 分足内のときだけ。
  `auto.symbol` が発注銘柄と違えば `shot.price` と `auto.price` の両方を使わない）。取り込みの実装は web 側（`lib/paper/resolve.ts` の `verifiedCurrentPrice`）が正。
