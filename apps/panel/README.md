# apps/panel — ペーパー発注の小窓

HYPER SBI 2 で値動きを見ながら、常に最前面の小窓でペーパー発注・決済・メモを記録する macOS アプリ。
**本物の発注は存在しない。** やることは `data/paper/events.jsonl` への追記（契約: `docs/paper-events.md`）と、
発注時の HYPER SBI 2 画面のスクショ保存（`data/paper/shots/YYYY-MM-DD/<event id>.png`）だけ。

## 構成

| パス | 中身 |
|---|---|
| `project.yml` | xcodegen の定義（`TradePanel.xcodeproj` はここから生成。生成物はコミットしない） |
| `App/` | `TradePanel.app` 本体（NSPanel を出すだけ）、`Info.plist`、`TradePanel.entitlements` |
| `PanelKit/` | ロジックと画面（framework）。イベント契約・再生（建玉の復元）・価格解釈・Vision 読み取り・ScreenCaptureKit 撮影・SwiftUI 画面 |
| `Tests/` | ユニットテスト（PanelKit だけを読み込む。小窓は画面に出ない・画面収録も使わない） |
| `scripts/` | `build.sh` / `test.sh` / `check-no-network.sh` |

## 必要なもの

- macOS 15 以上（開発は macOS 27 / Xcode 27 で確認）
- xcodegen（`brew install xcodegen`）
- 署名用の証明書 `Apple Development`（Team `9KT598FS4A`、DEVELOPMENT_TEAM で特定）がキーチェーンにあること。
  `security find-identity -v -p codesigning` で確認できる。

## ビルド・テスト・検査

```sh
cd apps/panel
./scripts/test.sh             # ユニットテスト（Debug）。見た目の確認用 PNG も shots-dev/ に書き出す
./scripts/build.sh            # Release ビルド → build/Build/Products/Release/TradePanel.app
./scripts/check-no-network.sh # 外部送信できないことの検査（違反なら exit 1）
```

`check-no-network.sh` が確かめること:
1. Swift ソースに通信・外部起動の API（URLSession、Network.framework、ソケット、NSWorkspace による URL 起動、WebKit、外部プロセス起動、URL 文字列など）が無い。
2. entitlements（ソースと、署名済みの成果物の両方）が App Sandbox あり・ネットワーク系（`network.client` / `network.server`）なし。
3. 成果物のバイナリが Network / WebKit / CFNetwork 等のフレームワークを直接リンクしていない。

App Sandbox を ON にしてネットワーク entitlement を付けていないので、OS のレベルでも外へは送信できない。
ファイルは、設定でユーザーが選んだフォルダ（security-scoped bookmark で記憶）の中にだけ書く。

## 起動

```sh
open apps/panel/build/Build/Products/Release/TradePanel.app
```

Dock には出ない（`LSUIElement`）。小窓を閉じるとアプリも終了する（書きかけの記録は書き切ってから終わる）。
設定は小窓の歯車ボタン、または小窓を選んだ状態で ⌘, 。

## 初回にやること（本人の操作が要る）

1. **データフォルダを選ぶ**: 初回起動で設定画面が開く。「選ぶ…」で `~/Project/tradelog/data/paper` を選ぶ
   （無ければダイアログ内で作る）。サンドボックスのため、ここで選んだフォルダにしか書けない。
2. **画面収録の権限**: 設定画面の「権限を求める」→ システム設定 > プライバシーとセキュリティ > 画面とシステムオーディオの収録 で
   「TradePanel（ペーパー発注）」を許可 → アプリを終了して起動し直す。
   - 毎回同じ Apple Development 証明書で署名しているので、再ビルドしても権限は外れない（ad-hoc 署名だと毎回外れる）。
   - macOS 15 以降は、画面収録を使うアプリに対して OS が定期的（約 1 か月ごと）に「引き続き許可するか」を確認してくることがある。その時は許可を選ぶ。
   - 権限が壊れた時のリセット: `tccutil reset ScreenCapture com.tomato.tradelog.panel`
3. **撮影対象のウィンドウ**: HYPER SBI 2 を起動した状態で「一覧を更新」→ 撮りたいウィンドウをタイトルで選ぶ
   （「自動」は画面に出ている最大のウィンドウ）。
4. **自動読み取りの確認**: HYPER SBI 2 の「全板」ウィンドウを出した状態で、設定画面の「自動読み取り」の「いま撮影」を押す。
   「現在値 5566（「5,566」）」「時刻 15:30」「銘柄 5803（タイトル…）」のように出れば設定はここまで。
   現在値は画面の「現在値」ラベルの右、銘柄コードはウィンドウタイトルの「(5803)」から読む。
5. **読み取り領域（任意：自動で読めない時だけ）**: 上で現在値・銘柄が「読めず」になる時だけ設定する。
   「現在値」を選んで「画面上で囲む」を押すと画面が暗くなり HYPER SBI 2 のウィンドウだけ黄色い枠で明るく残るので、実物の数字をマウスでドラッグして囲む
   （Esc で取り消し。選んでいる間は設定画面と小窓が隠れる）。囲んだ直後に 1 回撮影して読み、「切り出した拡大画像」と「生の文字列 → 解釈した値」が出るので、
   正しく読めるまで囲み直す。数字の周りに少し余白を取って囲むと安定する。現在値の領域を設定すると、発注時はその領域の値が優先される
   （領域はその場で読むので速い。全画面の自動読み取りは記録の後に裏で行う）。
   領域はウィンドウの大きさに対する比率で保存される（レイアウトを変えたら囲み直す）。
   HYPER SBI 2 をフルスクリーンにしている時は、そのスペースで小窓の歯車から設定画面を開いてから押す
   （HYPER SBI 2 が今の画面に出ていないと「画面に出ていません」と出て、オーバーレイは出ない）。

## 使い方

- **銘柄**: 小窓にマウスを乗せると、HYPER SBI 2 のウィンドウタイトルの「(5803)」（無ければ銘柄コード領域の読み取り）から自動入力する（1.5 秒に 1 回まで）。
  手で直した値は、HYPER SBI 2 側で別の銘柄に切り替わるまで上書きしない。虫眼鏡ボタンで強制的に読み直す。
- **株数**: 前回の値を覚える。
- **成行／指値**: 指値は「価格」欄に入れる（カンマ付きでも可）。
- **買い（赤）／売り（青）だけで新規・買い増し・決済・ドテン**: 1 銘柄に建玉は 1 つ（両建てしない）。
  ボタンの下に「押すと何が起きるか」が 1 行ずつ出る（例「売り 200 → 全決済」「売り 300 → 決済 200・新規売り 100（ドテン）」）。
  - 保有なし → 新規（売りの新規 = 空売り）。保有と同じ向き → 買い増し／売り増し。反対向きで保有数以下 → 一部決済・全決済。
  - 保有数を超える反対売買は**ドテン**（決済 + 反対向きの新規の 2 行を同じ時刻で記録）。ドテンになる時だけ、1 回目の押下ではボタンが橙の
    「もう一度でドテン」に変わって止まり、3 秒以内にもう一度押すと記録する（株数を前回値のまま押して意図せず反転するのを防ぐため）。
    銘柄・株数・成行/指値・価格を変えると予告は取り消される。記録の時刻は 2 回目に押した瞬間。
  - 待機中の指値は、約定すると両建てになるもの（反対向きの新規指値など）を発注と同時に取り消す（下の 1 行に「待機中の指値 N 件を取消」と出る）。
- 押した瞬間の時刻（ミリ秒）を記録し、HYPER SBI 2 を撮影して order を追記する。撮影対象のウィンドウは小窓にマウスが乗った時と 10 秒ごとに探し直して覚えておき、
  押した時は撮るだけにしている。撮れた時刻を `shot.captured_at` に残し、状態表示に「撮影 85ms」のように押下からの遅れを出す。
  撮影が 3 秒で終わらない・権限が無い等で撮れなくても、発注の記録は `shot: null` で必ず残る。
  画面全体の OCR（現在値・時刻・銘柄の自動読み取り）は記録の後に裏で行い、`shots/YYYY-MM-DD/<id>.ocr.json` に書く（形式は `docs/paper-events.md`）。
  読み取り領域の現在値は「数字・カンマ・小数点だけで、3 桁区切りが正しい」時だけ `price` に入れる。曖昧なら `null`（誤った値より null）。
- 撮影の遅れの計測: `log stream --predicate 'subsystem == "com.tomato.tradelog.panel"' --info` で、押下→撮影・PNG 保存＋領域 OCR・全画面 OCR の ms が出る。
- **建玉**: 方向・数量・平均建値（約定価格が 1 つでも不明なら「不明」。領域未設定なら全画面 OCR の現在値で表示）・経過時間と「全決済」（成行で保有全数）。
  一部決済は上の大きなボタンで行う。
- **待機中の指値**: 「約定した」（`fill_mark`）／「取消」（`cancel`）。ドテンの指値は「ドテン買 400株」のように 1 行にまとめ、2 行そろって約定・取消になる。
- **メモ**: 発注直後に自動でフォーカスが移る（音声入力でそのまま話せる）。⌘↩ で保存。対象の建玉はプルダウンで選べ、既定は直前に発注した建玉。
- 建玉・待機中の指値は、起動時に events.jsonl を頭から再生して復元する。

## 録画リプレイ練習

- **録画**: HYPER SBI 2 のウィンドウがある画面を、HYPER SBI 2 のウィンドウだけ 10fps 前後・実ピクセル（発注時の撮影と同じ。5K の画面なら 5120x2880）・カーソルなしで録る（HEVC、使えなければ H.264）。
  1x（論理ピクセル）の録画では全板の現在値（緑の数字）が OCR で読めなかったため実ピクセルにしている。
  画面に変化が無い間はフレームが来ないので可変フレームレート。保存先は `data/paper/replay/recordings/YYYY-MM-DD/<rec_id>.mp4` と `.json`（メタ。形式は `docs/paper-events.md`「リプレイ」）。
  録画中も発注できる。小窓の上に「録画中 08:57 / 残り 33 分」と出る（録画中に問題があれば「・黒い画面…」等を足し、終わると「録画終了 09:30・問題 N 件（…）」が残る）。
- **始め方**: 設定画面の「録画（リプレイ練習）」の「今すぐ録画（N 分）」、メニューの「リプレイ練習 > 今すぐ録画（37 分）」、
  起動引数 `--record-minutes N`（例 `open -g -a TradePanel.app --args --record-minutes 37`）、起動中のインスタンスには `open -g -a TradePanel.app 'tradepanel://record?minutes=37'`。
  録画中にもう一度指示すると、その時刻から N 分に締め切りを延ばす。平日 8:53 の自動録画はルートの README「常駐と自動実行」（launchd の `com.tomato.tradelog.record`）。
- **録画の失敗**: 権限なし・HYPER SBI 2 が無い・ScreenCaptureKit が止まった・黒い画面が続く（ロック・スリープの疑い）・60 秒以上フレームが来ない・ファイルに書けない、は
  必ずメタの `issues`、小窓の状態表示、`log stream --predicate 'subsystem == "com.tomato.tradelog.panel" && category == "record"'` の 3 か所に出る。
  ScreenCaptureKit が止まった時は数秒後に録り直す（その間の動画は直前のフレームのまま）。
- **練習**: 設定の一覧の「練習する」か、メニューの「リプレイ練習」から録画を選ぶ。再生ウィンドウ（再生・一時停止・シーク。速度は 1 倍だけ）に録画上の実時刻が大きく出て、
  小窓は紫地に「リプレイ: 2026-10-06 09:01:23」と出る。発注・メモは `data/paper/replay/events.jsonl` に書き（`ts` = 録画上の実時刻、`replay.video_ms` = 再生位置）、
  通常の events.jsonl・建玉とは混ぜない。練習を始めるたびに新しい session_id で、建玉は空から始まる。
  一時停止中と再生ウィンドウを閉じている時は発注・約定・取消・全決済を押せない（メモは書ける）。
  練習中は記録先（データフォルダ）を変えられない。最後に記録した発注・約定より前の位置にはシークできない（その位置に戻され、小窓に理由が出る。同じ練習の時刻が前後しないため）。閉じた再生ウィンドウは小窓の「再生画面」で出し直す。「練習を終える」で通常に戻る。
- **練習中の撮影**: 押した瞬間の録画のフレーム（許容誤差 0）から、発注銘柄のコードをタイトルに含む全板ウィンドウを切り出して `replay/shots/` に保存し、通常と同じく全画面 OCR のサイドカーを書く。
  発注銘柄の全板が無い時は、全板が 1 つだけならそれ、複数あればフレーム全体（この 2 つで銘柄が違う・決められない時は `auto.price` を null にする）。
  `auto.price` を入れるのは、切り出した全板のタイトルのコードが発注銘柄と一致した時だけ（コードが無い・違う全板 1 つを切り出した時も null）。
- **保存容量**: 自動では消さない。設定の一覧に本数と合計サイズ、各録画の長さ・サイズ・状態・問題が出る。「ゴミ箱へ移動」は Finder のゴミ箱に移すだけ（完全には消さない）。
  移せない時は理由が出るので Finder で `data/paper/replay/recordings/` から移す。
  設定には保存先ディスクの空きも出る。**空きが 5 GB 未満なら録画しない**（状態表示と record のログに理由が出る）。ゴミ箱に移しただけでは空きは戻らない（ゴミ箱を空にする）。
- **1 分あたりの容量（見込み）**: 平均ビットレートは 画素数 × 10fps × 0.06 ビット（`RecordingWriter.bitsPerPixel`）で、5120x2880 なら約 8.8 Mbps＝**1 分あたり最大 約 66 MB**。
  画面の変化が少ないと下回る。1x・2 Mbps だった 10-05 の実録画（1 分）は上限の約半分（7.6 MB/分）だったので、同じ比率なら **約 35 MB/分・37 分で約 1.3 GB（最大 約 2.5 GB）**、
  平日 20 日で約 25 GB（最大 約 50 GB）。実ピクセルでの実測はまだ無い（推測）。
- **1 分あたりの容量（実測）**: 実録画では **1 分 約 15 MB**、37 分で約 540 MB/日、20 営業日で約 11 GB。上の見込みより実測を正とする。

## 実機で本人が確かめること（ユニットテストでは確かめられない）

- 画面収録の権限付与と、HYPER SBI 2 の実画面での現在値・銘柄コードの自動読み取り精度（ザラ場で数回発注して、サイドカーの `auto.price` を目視照合）。
- 状態表示の「撮影 NNms」と、上のログで押下から撮影までの遅れ。
- 小窓がフルスクリーンの HYPER SBI 2 の上・別の Space にも出ること。
- 発注直後にメモ欄へフォーカスが移り、音声入力ソフトの文字（貼り付け方式でも）が入ること、⌘↩ で保存できること。
- 録画: 平日 8:53 の自動録画が始まること（`~/Library/Logs/tradelog/record.log` と設定の一覧）、録画中に発注できること、
  画面ロック中・ディスプレイが消えている間にどう録れるか（メタの `issues` の `locked` / `black` / `no_frames`）、37 分の録画のファイルサイズ。
- リプレイ: 録画を再生しながら発注し、切り出した全板の画像と自動読み取りの現在値が合っているか（実ピクセルの録画で現在値が読めるか）。
